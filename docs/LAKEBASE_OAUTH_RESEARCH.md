## 1. Executive Summary

Databricks Lakebase (PostgreSQL) supports **Machine-to-Machine (M2M) OAuth 2.0 authentication** using Service Principals. Rather than relying on static database passwords or secret scope strings that require manual rotation, applications authenticate via short-lived OAuth tokens (valid for 60 minutes) generated by the Databricks SDK (`WorkspaceClient`).

Furthermore, when deploying to Databricks Apps via Databricks Asset Bundles (DABs), environment variables are programmatically linked using resource bindings in `databricks.yml` and `valueFrom` references in `app.yaml`, allowing seamless host/user/database discovery without hardcoded credentials.

## 2. Technical Mechanism & Primary Source Findings

### 2.1 OAuth Authentication Flow
1. **Identity Provisioning:** A Service Principal is created in Databricks and assigned access to the Lakebase PostgreSQL instance / endpoint. In the database, a PostgreSQL role matching the Service Principal ID (or client ID) is created.
2. **Credential Generation:** The application uses `databricks.sdk.WorkspaceClient` to generate an OAuth credential:
   - Option A: `w.postgres.generate_database_credential(endpoint=endpoint_path)` — endpoint-scoped database credential token.
   - Option B: `w.config.get_token().access_token` — workspace-level M2M OAuth access token.
3. **PostgreSQL Connection String:** The OAuth token is passed as the **password** parameter in the PostgreSQL URI / `psycopg2.connect`:
   ```
   postgresql://<SERVICE_PRINCIPAL_CLIENT_ID>:<OAUTH_TOKEN>@<LAKEBASE_HOST>:5432/<DATABASE_NAME>?sslmode=require
   ```
4. **SSL Mode Requirement:** SSL is strictly enforced (`sslmode=require`) for all OAuth token-authenticated connections.

### 2.2 Token Lifetime & Rotation Strategy
- **Token Expiration:** OAuth tokens expire after 60 minutes.
- **Dynamic Retrieval Pattern:**
  - Connections created per-request or per-session should fetch the current OAuth access token via `WorkspaceClient` dynamically when opening new connections.
  - `get_lakebase_url()` in `src/db/connection.py` evaluates OAuth credentials dynamically so each new connection receives a valid token.

### 2.3 Programmatic Environment Linking in Deployed Databricks Apps
When deploying via Databricks Asset Bundles (DABs), environment linking works through two coordinated configuration files:

1. **`databricks.yml` (Infrastructure Resource Declaration):**
   Declares the Lakebase endpoint resource and binds it to the Databricks App spec:
   ```yaml
   resources:
     postgres_endpoints:
       dev_endpoint:
         parent: ${resources.postgres_branches.dev_branch.id}
         endpoint_id: 'primary'
     apps:
       capstone_app:
         name: capstone-research-app
         resources:
           - name: lakebase_db
             postgres_endpoint:
               endpoint_id: ${resources.postgres_endpoints.dev_endpoint.id}
               permission: CAN_CONNECT
   ```

2. **`app.yaml` (Runtime Environment Binding):**
   Links runtime environment variables using `valueFrom` or attached resource specs:
   ```yaml
   env:
     - name: LAKEBASE_USE_OAUTH
       value: "true"
     - name: LAKEBASE_HOST
       valueFrom: "lakebase_db.endpoint"
     - name: LAKEBASE_USER
       valueFrom: "lakebase_db.user"
     - name: LAKEBASE_DB
       valueFrom: "lakebase_db.database"
   ```

3. **Programmatic Resolution in Application Code (`src/db/connection.py`):**
   The application code reads these variables programmatically at runtime:
   ```python
   host = os.getenv("LAKEBASE_HOST") or os.getenv("PGHOST")
   user = os.getenv("LAKEBASE_USER") or os.getenv("PGUSER") or os.getenv("DATABRICKS_CLIENT_ID")
   db = os.getenv("LAKEBASE_DB") or os.getenv("PGDATABASE") or "databricks_postgres"
   
   if host and user:
       w = WorkspaceClient()
       token_info = w.config.get_token()
       token = token_info.access_token if token_info else ""
       return f"postgresql://{user}:{token}@{host}:5432/{db}?sslmode=require"
   ```

## 3. Current vs. Target Architecture

### Current Implementation (`src/db/connection.py`)
- Reads static `LAKEBASE_URL` from environment variables or fetches a stored connection string secret `lakebase_url` from secret scope `capstone_secrets`.
- Relies on static password credentials in the URI.

### Target Implementation (`src/db/connection.py`)
- **OAuth First / Auto-detection:**
  - Checks for OAuth mode explicitly (`LAKEBASE_USE_OAUTH=true`) or auto-detects presence of `LAKEBASE_HOST` / `PGHOST` along with Service Principal details (`DATABRICKS_CLIENT_ID` / `LAKEBASE_USER` or `WorkspaceClient` auth).
  - Uses `WorkspaceClient` to fetch a fresh OAuth token and construct the PostgreSQL URI.
- **Backward Compatibility:**
  - Falls back to `LAKEBASE_URL` / Databricks Secrets / mock mode if OAuth is not configured.
